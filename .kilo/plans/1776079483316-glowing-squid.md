# Task List for Purchase Order Functionality Improvements

## Overview
Implement enhancements to purchase order (PO) workflow based on user requirements:
1. Merge Confirm PO + Mark Delivered into one action with default Delivered = true
2. Auto-close PO when fully paid AND delivered
3. Surface unconfirmed PO signals in Routine Entry Card
4. Improve More Action Panel UX (close on outside click/ESC)

## Tasks

### 1. Confirm PO Action Enhancement
- [ ] Modify Confirm PO endpoint to always set status = CONFIRMED
- [ ] Add checkbox for "Mark as delivered" (pre-checked by default)
- [ ] When checkbox checked: also set delivered = true
- [ ] When checkbox unchecked: set delivered = false (PO becomes Confirmed but Pending Delivery)
- [ ] Update frontend Confirm PO modal to include checkbox
- [ ] Ensure backend does NOT collapse states (maintain Draft → Confirmed → Delivered → Closed)

### 2. Auto-close PO Logic
- [ ] Remove manual "Close PO" button from UI
- [ ] Implement auto-close logic: IF (total_paid >= total_amount) AND (delivered = true) → status = CLOSED
- [ ] Update status display logic:
  - Paid but not delivered → "Awaiting Delivery"
  - Delivered but unpaid → "Pending Payment"
  - Both done → "Closed" (auto)
- [ ] Verify edge cases: prevent closing PO that hasn't been delivered

### 3. Routine Entry Card Enhancement
- [ ] Add status indicator badge/icon for unconfirmed POs:
  - Show ⚠️ "Unconfirmed PO" or count: "X Pending PO"
  - Keep subtle, not noisy
- [ ] Modify "Record Payment" action to trigger confirmation flow for unconfirmed POs:
  - Show mini inline confirmation when PO is unconfirmed:
    - "This PO is not confirmed."
    - [✓] Confirm and mark as delivered (default)
    - [ ] Confirm only (not delivered)
  - Apply default delivery = true when confirmed via payment

### 4. More Action Panel UX Improvements

- [ ] Test responsiveness and UX hygiene
